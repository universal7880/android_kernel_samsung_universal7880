Samsung Galaxy A5/A7 2017 board selection
=======================================

Board DT root property:

- samsung,board-id: one of "a5y17lte-eur", "a5y17lte-can",
  "a5y17lte-kor", "a7y17lte-eur" or "a7y17lte-kor".

This identifies the model and regional configuration independently of the
human-readable model name. Existing model_info-hw_rev and
model_info-hw_rev_end properties give the inclusive hardware revision range.
The region is not interchangeable with the hardware revision.

The shared bootstrap uses compatible "samsung,a5a7y17lte". Its original
/chosen/bootargs supplies androidboot.bootloader and androidboot.hw_rev.
A520F selects A5 EUR, A520W A5 CAN, A520K/L/S A5 KOR, A720F A7 EUR and
A720S A7 KOR. Unknown models and ambiguous revision matches are rejected.
Live demo unit descriptions are not part of the board catalogue.

CONFIG_EXYNOS7880_BOARD_DTBS embeds the existing regional DTBs and the
unmodified bootstrap in .dtb.init.rodata, using the standard kernel DTB
linker section. The catalogue is separate from the DTBH image and is
released with the kernel's init memory. It adds no new compiler or library
dependency. It is disabled in the regular device defconfigs.

The selected board tree is completed before early memory scanning. Firmware
changes are obtained by comparing the incoming bootstrap with its pristine
catalogue copy. Recognized changes to chosen, memory, reserved-memory, ECT,
serial-number and MAC properties are replayed onto the selected board tree.
The header reservation map and boot CPU ID are preserved as well.

DT structure checks use libfdt 1.7.2 with its upstream trailing-NOP fix.
Board selection additionally rejects duplicate paths and properties,
overlapping data blocks, overflowing reservations and excessive nesting.

This is deliberately not a general overlay mechanism. Unknown firmware
changes, changes to phandle declarations, incompatible boot-data layouts,
ambiguous identities and malformed trees are rejected. Board-specific
phandles remain those of the selected complete DT, rather than being merged
from a different model. The prepared DT occupies a permanent 512 KiB buffer:
flat-tree consumers can retain pointers after init memory has been freed.

This remains a staged implementation. It does not change DTBH packaging or
create a unified ROM product, and the bootstrap is not included in regular
per-device DTBH images. Before enabling it, check the final kernel size and
bootloader memory placement, and validate firmware changes and board
selection on physical A5 and A7 devices. Ordinary device trees continue to
use their existing hardware descriptions.
